# genai — 証跡付き・完全オフラインのローカルRAG

**預かった文書を外部に一切送信せずにAIへ質問でき、「送信していないこと」を実行のたびに証跡として自動で記録するツールです。**

機密情報を扱うなど、文書を外部のAIサービスへ送信できない業務での利用を想定しています。手元の文書（テキスト／Markdown）を根拠に質問へ回答する最小構成のRAG（関連部分を検索してLLMに渡す方式）で、**外部APIを使わず、機内モードでも動作します**。追加の依存ライブラリはなく、Python標準ライブラリだけで動きます。

主な機能は次の3つです。

1. **ローカルRAG** — `docs/` の文書を根拠に、ローカルLLMが出典付きで回答します
2. **非送信の証跡** — 実行のたびに、外部との疎通チェックの結果と、入出力・コードのSHA-256ハッシュを `evidence.jsonl` に追記します。記録はハッシュチェーン（各記録が直前の記録のハッシュを含む形式）でつながっているため、後からの改ざんや削除を検出できます
3. **1行で切り替え** — Ollama と LM Studio を config.py の1行で切り替えられます

## 検証環境

- メモリ16GBのノートPC（Windows 11）＋ WSL2（Ubuntu、**メモリ割り当て 7.6GB**）
- Ollama 0.32 系
- Python 3.14（WSL標準の python3）

WSLへの割り当てが実機メモリの約半分という、16GBをそのまま使うよりも厳しい条件で動作を確認しています。

## 使用モデルとメモリの目安

| モデル | 役割 | サイズ |
|---|---|---|
| gemma3:4b | 回答生成 | 約3.3GB |
| bge-m3 | 埋め込み（日本語対応） | 約1.2GB |

2つ合わせて約4.5GBなので、割り当て7.6GBでも余裕があります。qwen3:8b（5.2GB）を使う場合は、埋め込みモデルと同時に常駐させるとメモリが窮屈になるため、`ollama stop` で片方を降ろしながら運用することをおすすめします。

## セットアップ

```bash
ollama pull gemma3:4b
ollama pull bge-m3
```

作業フォルダは **WSLのLinux側**（例: `~/genai`）に置いてください。`/mnt/c` 経由ではファイルアクセスが遅く、文字コードのトラブルの原因にもなります。

読ませたい文書（UTF-8の .txt / .md）は `docs/` にコピーします。Windows側にあるファイルは、次のようにコピーできます。

```bash
cp /mnt/c/Users/<ユーザー名>/Documents/gl.txt ~/genai/docs/
```

## 使い方

```bash
# 1. 文書をインデックス化（docs/ を変更したら再実行）
python3 ingest.py

# 2. 質問する
python3 ask.py "個人情報は入力していい？"

# 参照したチャンクの本文も見たいとき
python3 ask.py --show "ローカル環境での利用に制限はある？"
```

## ブラウザ画面で使う

```bash
python3 serve.py
```

を実行してから、ブラウザで http://127.0.0.1:8765 を開くと、質問の入力、回答の表示、証跡の状態（オフラインで実行されたかどうか）を確認できる画面が表示されます。

構成は **serve.py（Python標準ライブラリの http.server のみ）と ui.html（素のHTML/CSS/JavaScriptの1ファイル）だけ**です。フレームワーク、ビルド、外部CDNの読み込みはありません。127.0.0.1 にのみバインドするため、他の端末からはアクセスできません。機内モードでもそのまま動きます。

## LM Studio への切り替え

[config.py](config.py) の先頭 **1行** を書き換えるだけです。

```python
PROVIDER = "lmstudio"  # ← "ollama" から変更
```

LM Studio 側では「ローカルサーバー」を起動し（既定ポート 1234）、`SETTINGS["lmstudio"]` のモデル名を、読み込んでいるモデルに合わせてください。コードは両者に共通する OpenAI 互換 API（`/v1/chat/completions`, `/v1/embeddings`）だけを使っています。

## 非送信の証跡（evidence.jsonl）

`ask.py` を実行するたびに、`evidence.jsonl` へ1行追記されます。各レコードの内容は次のとおりです。

- **外部との疎通チェックの結果** — 1.1.1.1:443 / 8.8.8.8:53 へのTCP接続とDNS解決を試みた結果です（接続を試みるだけで、データは送りません）。**すべて失敗していれば、通信が遮断された状態で実行された証拠**になります
- **入出力のハッシュ** — 質問・回答・index.json・コード5ファイルの SHA-256
- **ハッシュチェーン** — 各レコードが直前のレコードのハッシュを含むため、過去のレコードの改ざん・削除・並べ替えは検証時に検出されます

```bash
# チェーンの検証
python3 evidence.py --verify
```

委託元に示す際は、機内モードで実行したときのレコード（`"offline": true`）と検証結果を見せることで、「この質問応答は外部と通信できない状態で行われた」ことを、スクリーンショットよりも確かな形で示せます。

## オフライン動作の証跡の取り方

1. `ollama pull` によるモデルの取得だけは通信が必要なので事前に済ませ、`ingest.py` まで実行しておきます（埋め込み自体に通信は不要です）
2. Windows の**機内モードをオン**にします（WSL側の通信も一緒に切れます）
3. `curl -m 3 https://example.com` で通信が切れていることを確認します（接続に失敗すれば、通信は切れています）
4. その状態で `python3 ask.py "..."` を実行し、回答が返る画面を撮影します
5. 機内モードをオフに戻します

## 仕組み

```
docs/*.txt ─ ingest.py ─→ 文字数ベースで分割 ─→ bge-m3 で埋め込み ─→ index.json
質問 ──────  ask.py  ──→ 質問を埋め込み → コサイン類似度で上位3件 → gemma3:4b が根拠付きで回答
```

- [config.py](config.py) — 接続先・モデル・チャンクの設定
- [llm.py](llm.py) — OpenAI互換APIのクライアント（urllib のみ）
- [ingest.py](ingest.py) — 文書の分割・埋め込み・保存
- [ask.py](ask.py) — 検索と回答生成（実行ごとに証跡を自動記録）
- [evidence.py](evidence.py) — 非送信の証跡の記録と検証
- [serve.py](serve.py) / [ui.html](ui.html) — ブラウザ画面（標準ライブラリと素のHTML/CSS/JSのみ）
