# genai — 証跡付き・完全オフラインのローカルRAG

**この製品は、預かった文書を一切外部に送信せずにAIへ質問でき、かつ「送信していないこと」を実行のたびに証跡として自動記録する製品です。**

業務委託契約の「生成AI利用禁止・制限」条項に直面した受託者を想定しています。
手元の文書（テキスト/Markdown）を根拠に質問へ回答する最小構成のRAGで、
**外部APIを一切使わず、機内モードでも動作**します。依存ライブラリもゼロ（Python標準ライブラリのみ）。

できることは3つです。

1. **ローカルRAG** — `docs/` の文書を根拠に、ローカルLLMが出典付きで回答する
2. **非送信証跡** — 実行のたびに、外部疎通チェックの結果と入出力・コードのSHA-256ハッシュを
   ハッシュチェーンで `evidence.jsonl` に追記する（後からの改ざん・削除を検出可能）
3. **1行切替** — Ollama と LM Studio を config.py の1行で切り替えられる

## 検証環境

- 16GBメモリのノートPC（Windows 11）＋ WSL2（Ubuntu、**メモリ割当 7.6GB**）
- Ollama 0.32 系
- Python 3.14（WSL標準の python3）

WSLへの割当が実機の半分という、実機16GBよりさらに厳しい条件で動作確認しています。

## 使用モデルとメモリの目安

| モデル | 役割 | サイズ |
|---|---|---|
| gemma3:4b | 回答生成 | 約3.3GB |
| bge-m3 | 埋め込み（日本語対応） | 約1.2GB |

2つ合わせて約4.5GBなので、割当7.6GBでも余裕があります。
qwen3:8b（5.2GB）を使う場合は埋め込みモデルとの同時常駐が窮屈になるため、
`ollama stop` で片方を降ろしながらの運用を推奨します。

## セットアップ

```bash
ollama pull gemma3:4b
ollama pull bge-m3
```

作業フォルダは **WSLのLinux側**（例: `~/genai`）に置いてください。
`/mnt/c` 経由はファイルアクセスが遅く、文字コードのトラブルの元になります。

読ませたい文書（UTF-8の .txt / .md）は `docs/` にコピーします。
Windows側にあるファイルはこうコピーできます:

```bash
cp /mnt/c/Users/<ユーザー名>/Documents/gl.txt ~/genai/docs/
```

## 使い方

```bash
# 1. 文書をインデックス化（docs/ を変更したら再実行）
python3 ingest.py

# 2. 質問する
python3 ask.py "個人情報は入力していい？"

# 参照したチャンクの本文も見たいとき
python3 ask.py --show "ローカル環境での利用に制限はある？"
```

## ブラウザ画面で使う

```bash
python3 serve.py
```

を実行して、ブラウザで http://127.0.0.1:8765 を開くと、質問入力・回答表示・
証跡の状態（オフライン実行かどうか）が見える画面になります。

構成は **serve.py（Python標準ライブラリの http.server のみ）と ui.html（素のHTML/CSS/JavaScript 1ファイル）だけ**です。
フレームワークなし、ビルドなし、外部CDNの読み込みなし。127.0.0.1 にしか
バインドしないため、他の端末からはアクセスできません。機内モードでもそのまま動きます。

## LM Studio への切り替え

[config.py](config.py) の先頭 **1行** を書き換えるだけです。

```python
PROVIDER = "lmstudio"  # ← "ollama" から変更
```

LM Studio 側は「ローカルサーバー」を起動し（既定ポート 1234）、
`SETTINGS["lmstudio"]` のモデル名をロード中のモデルに合わせてください。
コードは両者共通の OpenAI 互換 API（`/v1/chat/completions`, `/v1/embeddings`）だけを使っています。

## 非送信証跡（evidence.jsonl）

`ask.py` を実行するたびに `evidence.jsonl` へ1行追記されます。各レコードの内容:

- **外部疎通チェックの結果** — 1.1.1.1:443 / 8.8.8.8:53 へのTCP接続とDNS解決を試みた結果
  （接続試行のみでデータは送りません）。**全滅していれば「遮断状態で実行された」証拠**になります
- **入出力のハッシュ** — 質問・回答・index.json・コード5ファイルの SHA-256
- **ハッシュチェーン** — 各レコードは直前レコードのハッシュを含むため、
  過去のレコードの改ざん・削除・並べ替えは検証で検出されます

```bash
# チェーンの検証
python3 evidence.py --verify
```

委託元に提示するときは、機内モードで実行した際のレコード（`"offline": true`）と
検証結果を見せれば、「この質問応答は外部と通信できない状態で行われた」ことを
スクリーンショットより強い形で示せます。

## オフライン動作の証跡の取り方

1. `ingest.py` まで済ませておく（モデルの取得と埋め込みには通信不要だが、pull だけは事前に）
2. Windows の**機内モードを ON**（WSL側の通信も一緒に切れる）
3. 通信が切れていることを確認: `curl -m 3 https://example.com`（失敗すればOK）
4. その状態で `python3 ask.py "..."` を実行し、回答が返る画面を撮影
5. 機内モードを OFF に戻す

## 仕組み

```
docs/*.txt ─ ingest.py ─→ 文字数ベースで分割 ─→ bge-m3 で埋め込み ─→ index.json
質問 ──────  ask.py  ──→ 質問を埋め込み → コサイン類似度で上位3件 → gemma3:4b が根拠付きで回答
```

- [config.py](config.py) — 接続先・モデル・チャンク設定
- [llm.py](llm.py) — OpenAI互換APIクライアント（urllib のみ）
- [ingest.py](ingest.py) — 文書の分割・埋め込み・保存
- [ask.py](ask.py) — 検索と回答生成（実行ごとに証跡を自動記録）
- [evidence.py](evidence.py) — 非送信証跡の記録と検証
- [serve.py](serve.py) / [ui.html](ui.html) — ブラウザ画面（標準ライブラリ＋素のHTML/CSS/JSのみ）
