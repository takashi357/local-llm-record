# 閉域環境でのローカルLLM出力検収

通信を遮断したノートPC1台で、行政が公開しているガイドライン文書から
職員が守るべき事項を抽出し、その出力を原典の項目と自動で照合する。

## 何をするものか

- `run.py` … 文書の全文と設問を、手元で動くモデルに渡し、表を作らせる
- `check.py` … 出てきた表の各行を原典の項目と突き合わせ、
  当たった行・当たらなかった行・抜け落ちた項目・重複を出す

## 背景

同じ端末・同じモデル・同じ文書でも、アプリの画面から実行すると
文書の一部だけが渡され、重要な項目が抜け落ちることがある。
全文を自分で渡す形にすると、抜けはなくなった。

さらに、照合を書いた側にも誤りが出た。
最初の版は表記の違いを吸収できず、出力に存在する項目を
「現れなかった」と誤って報告した。
出力を確かめる仕組みそのものにも、確かめる工程が要る。

## 動作環境

- Windows 11 / Python 3.13（追加ライブラリなし。標準機能のみ）
- LM Studio 0.4.20 のローカルサーバー（http://127.0.0.1:1234）
- モデル：openai/gpt-oss-20b（GGUF・MXFP4・12.11GB）
- コンテキスト長 32768 / temperature 0
- メモリ16GBの端末でWSL経由のLinuxを使う場合、既定の割当は7.6GBとなり、本ツールが前提とする12.11GBのモデルは読み込めない。詳細は `measurements/` を参照

## 実行

1. LM Studioでモデルを読み込み、Developer → Start Server
2. 対象文書のテキストを `gl.txt` として同じ場所に置く
3. `python run.py` → 出力が `out.txt` に保存される
4. `python check.py` → 照合結果が表示される

## 実測

- 入力 8,343トークン / 出力 874トークン / 所要 81.54秒
- 出力10行に対し、原典の遵守事項6項目すべてが含まれていた（欠落0件）
- 実行はすべて機内モードで行った

## 抜き出して渡した場合(rag.py)

同じ端末・同じ文書・同じ設問で、全文を渡す代わりに、関連しそうな箇所だけを抜き出して渡した記録。

文書を800字ごと(150字重ね)に区切ると23か所になる。設問と近い順に上位k件を選び、その分だけを渡して同じ表を作らせた。埋め込みには nomic-embed-text-v1.5 を使用。追加ライブラリは無し。

### 対象文書

福岡県「生成AI庁内利活用ガイドライン(第2.2版)」(令和8年4月1日)

原典: https://www.pref.fukuoka.lg.jp/uploaded/attachment/282910.pdf

本文(gl.txt)は転載を避けるため同梱していない。再現するには上記PDFからテキストを抽出し、`gl.txt` として同じフォルダに置く。同一性の確認用に、当方で使用したファイルの値を記載する。

- サイズ: 34,047バイト(UTF-8)
- SHA-256: 65de069774b147fd1dbb028c4cea8c334ed92f882a1041ad1d46202c35ce94b5
- 800字/150字重ねで区切ったときのチャンク数: 23

抽出方法の違いで改行や空白が変わると、この値は一致せず、区切り位置もずれて結果が変わりうる。

### 実測

| k | 入力トークン | 所要秒 | 出力行数 | 遵守6項目 | 選ばれた箇所 |
|---|---|---|---|---|---|
| 3 | 1,909 | 46.55 | 5 | 1 | 12,16,19 |
| 5 | 3,087 | 50.10 | 4 | 0 | 11,12,16,17,19 |
| 8 | 4,793 | 70.49 | 7 | 2 | 9〜12,16,17,19,20 |
| 12 | 7,019 | 66.86 | 7 | 4 | 7〜12,15〜20 |
| 23 | 10,256 | 91.20 | 10 | 6 | 全件 |

遵守6項目=QT-GenAIに限定／使用対象者の限定／テキスト以外の制限／機密性1(個人情報)の禁止／約款型サービスの事前協議／生成内容の信頼性確認。

6項目の判定は、出力の各行が原典の規定と同じ義務を述べているかを1行ずつ照合した。単語の一致による自動判定は、無関係な行を拾い、言い換えられた行を落とす誤りが出たため採用していない。

### 分かったこと

揃う件数は無かった。半分(12か所)を渡しても4項目で止まり、全件を渡してようやく6項目が揃う。

件数を増やせば単調に良くなるわけでもない。3件で5行・1項目、5件で4行・0項目と、渡す量を増やしたのに行も項目も減った。顔ぶれも入れ替わり、3件と5件で共通する行は1つだけだった。

k=12の入力は7,019トークンで、全件の10,256の約7割にあたる。量を削るために抜き出しているのに、7割を渡してなお2項目が欠けている。

最も大きいのは選ばれた場所である。義務の本体が書かれた章(2.1)はチャンク13〜15にあるが、このうち13と14は、k=3でも5でも8でも12でも一度も選ばれなかった。守るべき事項を問う設問に対し、守るべき事項の章が選ばれないまま表が作られていた。k=8以降に現れたQT-GenAI限定や事前協議は、第4章(対象外サービスの章)にある言い直しから拾われたものである。

出典の表示が揺れた原因もここにある。同じ規定が2.1と第4章の2か所に書かれており、どちらの箇所が渡ったかで、同じ義務に別の章が付いた。

### 実行

```
python rag.py 3
```

出力は out_k3.txt に保存される。全実行は機内モード。

### 注意

k=23は全件を渡しており、抜き出しではなく全文注入と同じ状態にあたる。「23件なら足りる」ではない。

この結果はこの文書・この区切り方・この埋め込みモデルでのもの。庁内ネットワークでの動作は保証しない。

k=23の入力(10,256トークン)が全文注入(8,343トークン)より多いのは、区切りの重ね部分(150字×22か所)が重複して渡るためである。

## 道具箱への拡張（2026年）

上記の検収記録を土台に、閉域ローカルLLMの「入口から定着まで」を揃えた。
共通の骨格は「業務理解・課題特定 → 設計 → 実装 → 定着 → 成果 → ＋再現性」の6段
（詳細は [fde/README.md](fde/README.md)）。

- [model-check/](model-check/) — モデル受け入れ検査。公開リポジトリ由来のモデルを実行せずに検査する（pickle系の拒否・GGUF/safetensorsヘッダ解析・SHA-256照合・メモリ適合判定）
- [genai/](genai/) — 7.6GB割当のWSLでも動く構成（gemma3:4b＋bge-m3、実測4.1GB常駐）。実行ごとに外部疎通チェックと入出力ハッシュを連鎖記録する非送信証跡、ブラウザUI付き（すべてPython標準ライブラリ＋素のHTML/CSS/JS）
- [fde/](fde/) — フルリモートFDEジョブエイド（6フェーズ24項目）と、生成AI配置判定エイド（デジタル庁DS-920基準で約款型／専用環境／ローカルを判定）
- [learning-log/](learning-log/) — 検証可能な学習ログ（ハッシュチェーン。事後登録は明示区別）

「動作環境」に記した「WSL割当7.6GBでは12.11GBのモデルが載らない」という制約への回答が genai/ にあたる。
